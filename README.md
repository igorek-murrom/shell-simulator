# Эмулятор командной оболочки

## Общее описание

Практическая работа, вариант 16.

Консольный эмулятор UNIX-подобной оболочки на Python 3.9 или новее,
без сторонних библиотек. Реализованы этапы 1–5: REPL, конфигурация,
стартовые скрипты, JSON VFS, основные команды и удаление.
Сборка и установка зависимостей не требуются.

VFS загружается один раз. Дерево каталогов и содержимое файлов находятся
в памяти: исходный JSON не изменяется, файлы на диск не распаковываются.
Виртуальный текущий каталог начинается с `/`; имя пользователя и имя
компьютера в приглашении берутся из реальной ОС.

## Структура проекта

* `src/shell_emulator/` — исходный код;
* `tests/` — автоматические тесты;
* `scripts/` — стартовые сценарии и скрипты реальной ОС;
* `vfs/` — текстовые JSON-примеры VFS;
* `run.sh`, `run.bat` — запуск в Linux и Windows.

## Основные функции

* `ls [-lha] [PATH]` — выводит отсортированные имена в каталоге, по одному
  на строку. Без пути использует текущий каталог. Для файла печатает его путь.
  `-a` включает скрытые имена и `.`/`..`; `-l` показывает тип, права, число
  ссылок, владельца, группу, размер в байтах, дату и имя; `-h` вместе с `-l`
  показывает размеры в единицах K/M/G и далее (основание 1024).
  Флаги можно сочетать: `ls -lah`, `ls -l -h -a`, `ls -alh` равнозначны.
  Без `-l` флаг `-h` не меняет вывод. Для пустого каталога без `-a` вывод пуст.
* `cd [PATH]` — меняет виртуальный текущий каталог. Без аргумента переходит
  в `/`: домашний каталог реальной ОС не переносится в VFS. Поддерживает
  абсолютные и относительные пути, `.`, `..`, повторные `/` и кавычки.
  При ошибке текущий каталог сохраняется. Каталог в приглашении обновляется.
* `uniq [-c|-d|-u] FILE` — читает UTF-8-файл из памяти и объединяет только
  соседние одинаковые строки. `-c` печатает число строк в каждой группе,
  `-d` — только повторяющиеся группы, `-u` — только одиночные группы.
  Допустим один режим. Пустой файл даёт пустой вывод; отсутствие последнего
  перевода строки сохраняется для выводимой строки. Разделитель строк — LF,
  CR сохраняется как часть текста. Выходной файл и чтение stdin не поддержаны.
* `whoami` — печатает имя пользователя реальной ОС, как в приглашении.
  Аргументы запрещены.

* `rm [-rRf] PATH...` — удаляет виртуальные файлы. `-r` и `-R` позволяют
  удалить каталог с его содержимым; `-f` пропускает отсутствующие пути
  и допускает отсутствие аргументов. Сочетания `-rf`, `-Rf` поддерживаются.
  `-f` не скрывает ошибки типов, неверных путей или защищённых каталогов.
* `rmdir PATH...` — удаляет только пустые виртуальные каталоги.
  Файлы, непустые каталоги и неподдерживаемые флаги вызывают ошибку.

Удаление выполняется только в памяти: JSON и файлы реальной ОС не меняются.
Новый запуск восстанавливает VFS из JSON. Корень, текущий каталог, его предки
и пути с последним компонентом `.` или `..` защищены от удаления, чтобы
текущий виртуальный каталог оставался доступен. Несколько путей удаляются
по порядку до первой ошибки; уже выполненные удаления не откатываются.
Все аргументы и опции разбираются до начала удаления.

`ls`, `cd`, `uniq`, `rm`, `rmdir` поддерживают `--` перед именами, начинающимися с `-`.
Неподдерживаемые опции, лишние аргументы, отсутствующие пути, переход в файл,
чтение каталога через `uniq` и файл с неверным UTF-8 вызывают ошибку.
Все пути команд относятся к VFS, включая раскрытые переменные окружения.

* `exit` — завершает сеанс; аргументы запрещены.
* `parse_line()` — раскрывает `$NAME` и `${NAME}` из окружения реальной ОС,
  затем разбирает кавычки и аргументы. Неизвестные переменные сохраняются.
  Раскрытие выполняется перед разбором кавычек, в том числе внутри одинарных
  кавычек; значения с пробелами следует заключать в двойные кавычки.
* `build_prompt()` — формирует `username@hostname:path$`.
* `ShellEmulator.execute_line()` — разбирает и исполняет одну команду.
* `run_interactive()` — выполняет REPL до `exit` или конца ввода;
  после ошибки можно продолжать работу.
* `run_script()` — показывает ввод и вывод, пропускает пустые строки,
  останавливается при первой ошибке или `exit`.
* `VirtualFileSystem.load()` — проверяет JSON и загружает дерево в память.
* `get_node(path, cwd='/')` — ищет виртуальный узел по абсолютному или
  относительному UNIX-пути; поддерживает `.`, `..` и повторные `/`.
  Переход выше корня остаётся в корне. Переход через файл запрещён.
* `list_directory(path='/', cwd='/')` — возвращает имена в алфавитном порядке.
* `read_file(path, cwd='/')` — возвращает содержимое файла как `bytes`.
* `remove(path, cwd, recursive, directory_only, missing_ok)` — удаляет узел
  из памяти после проверок пути и типа.
* `absolute_path(path, cwd)` — нормализует проверенный виртуальный путь.
* `statistics()` — считает каталоги (включая корень), файлы и байты.
* `ShellState` — хранит VFS и виртуальный текущий каталог;
  `ShellContext` — передаёт состояние и поток вывода обработчикам.
* `VFSError` — сообщает об ошибках загрузки и обращения к VFS.

Методы VFS — программный интерфейс, а не новые команды оболочки.
Неизвестные команды, лишние аргументы и незакрытые кавычки вызывают ошибку.

## Настройки

Поддерживаются параметры:

```text
--vfs PATH
--script PATH
```

`--vfs` задаёт путь к JSON-файлу VFS.
Без параметра создаётся пустой корневой каталог в памяти.

`--script` задаёт путь к стартовому скрипту эмулятора.
Без параметра запускается интерактивный режим.

Относительные пути отсчитываются от каталога запуска.
При запуске оба параметра выводятся в отладочном режиме.
После загрузки VFS выводятся числа каталогов, файлов и байтов.

Ошибка загрузки VFS прекращает запуск до выполнения команд.
Ошибка VFS или стартового скрипта возвращает код `1`,
успешное выполнение — `0`, ошибка параметров запуска — `2`.
Интерактивный сеанс возвращает `0`, даже если были ошибки команд.

## Стартовый скрипт

Команды записываются по одной на строку в текстовом файле.
Пустые строки пропускаются. При выполнении отображаются
и введённая команда, и её вывод.

Стартовые скрипты эмулятора `.txt` запускаются через ключ `--script`:

```bash
./run.sh --vfs vfs/deep.json --script scripts/stage3_success.txt
```

При первой ошибке выполнение скрипта прекращается.
После сообщения о причине ошибки выводится итоговая строка
`Execution finished with errors.`. В интерактивном режиме эта
строка выводится при завершении сеанса, если возникали ошибки.
Строки после ошибки в скрипте и после `exit` не выполняются.

```bash
PYTHONPATH=src python3 -m shell_emulator --vfs vfs/deep.json
```

## Формат VFS

Корень — объект `directory` с именем `/` и списком `children`.
Каждый дочерний узел — каталог или файл. Имена внутри одного каталога
уникальны и не содержат `/`, `\`, нулевой символ; `.` и `..` запрещены.
Все обязательные поля должны присутствовать; неизвестные поля и повторные
ключи JSON отклоняются. Все имена и содержимое чувствительны к регистру.

```json
{
  "type": "directory",
  "name": "/",
  "children": [
    {"type": "file", "name": "hello.txt", "content": "Привет!\n"},
    {
      "type": "file",
      "name": "data.bin",
      "encoding": "base64",
      "content": "AAEC/w=="
    },
    {"type": "directory", "name": "docs", "children": []}
  ]
}
```

Для файлов обязательны `type`, `name`, `content`. Поле `encoding`:
`utf-8` (по умолчанию) или `base64`. В памяти текст становится UTF-8-байтами,
а base64 — исходными двоичными байтами. Приведённый base64 означает
`00 01 02 ff`. Неверный base64 и другие кодировки отклоняются.
Каталог содержит только `type`, `name`, `children`.

Для `ls -l` JSON не требует новых полей. Виртуальные права по умолчанию:
`drwxr-xr-x` для каталогов, `-rw-r--r--` для файлов. Владелец — текущий
пользователь ОС, группа — `vfs`. Число ссылок файла равно 1, каталога — 2
плюс число непосредственных подкаталогов. Размер файла — длина его байтов,
каталога — 0. Дата узла задаётся при загрузке; после удаления дата родителя
обновляется в памяти. Атрибуты используются только для отображения;
проверки прав доступа и изменение прав не реализованы. Строка `total`
не выводится, поскольку эмулятор не моделирует дисковые блоки.

Примеры:

* `vfs/minimal.json` — пустой корень;
* `vfs/several.json` — три файла: UTF-8-текст, имя с пробелом, двоичные данные;
* `vfs/deep.json` — три вложенных уровня каталогов, файлы на каждом уровне;
* `vfs/stage4.json` — скрытый файл, пустые файл и каталог,
  имя с пробелом, имя с дефисом, повторы и неверный UTF-8;
* `vfs/stage5.json` — файлы и пустые каталоги, скрытые имена,
  имена с пробелом и дефисом, дерево из трёх уровней для удаления.
  `large.txt` содержит 1536 байт: `ls -l` показывает `1536`,
  а `ls -lh` — `1.5K`.

## Проверка третьего этапа

Скрипты `.sh` запускаются оболочкой реальной ОС.
Они сами вызывают эмулятор с нужными параметрами:
стартовые `.txt` передают через `--script`,
а интерактивные команды подают через стандартный ввод.

```bash
bash scripts/stage3_vfs.sh
bash scripts/stage3_interactive.sh
bash scripts/stage3_errors.sh
```

Каждый скрипт запускает эмулятор с минимальной VFS, несколькими файлами
и глубоким деревом. Скрипты работают из любого каталога запуска.
`stage3_vfs.sh` выполняет успешный стартовый сценарий.
`stage3_interactive.sh` подаёт команды в REPL и показывает продолжение
после ошибки. `stage3_errors.sh` проверяет код `1` для каждой ожидаемой
ошибки, включая отсутствующий JSON, неверный JSON, структуру и base64.
Временные некорректные JSON создаются вне проекта и удаляются после запуска.

`stage3_success.txt` проверяет `ls` и `cd` на корневом каталоге,
доступном во всех трёх VFS, и завершение через `exit`.
После этапа 4 сценарии этапов 2–3 адаптированы к реальным командам.
Загрузку содержимого и вложенные пути также проверяют автотесты.

Ошибки вынесены в отдельные стартовые сценарии, потому что вариант 16
требует остановки при первой ошибке:

* `stage3_unknown.txt` — неизвестная команда;
* `stage3_ls_error.txt`, `stage3_cd_error.txt` — лишние аргументы;
* `stage3_exit_error.txt` — аргумент у `exit`;
* `stage3_syntax_error.txt` — незакрытая кавычка.

Строки после ошибки и после `exit` не выполняются.
Сценарии этапа 2 также сохранены в `scripts/stage2_*`.

Например, проверить остановку при неизвестной команде можно так:

```bash
./run.sh --vfs vfs/deep.json --script scripts/stage3_unknown.txt
```

Сообщение `error:` и код `1` в этом случае ожидаемы.

## Проверка четвёртого этапа

```bash
./run.sh --vfs vfs/stage4.json --script scripts/stage4_success.txt
bash scripts/stage4_all.sh
```

Успешный стартовый сценарий показывает все поддерживаемые режимы новых
команд, абсолютные и относительные пути, пустые каталоги и файлы, скрытые
имена, кавычки и `--`. Скрипт реальной ОС работает из любого каталога,
запускает успешный сценарий, все 17 ошибочных `stage4_*.txt` и REPL.
Он проверяет код `1` каждого ошибочного сценария, а автотесты дополнительно
проверяют остановку до `must_not_execute` и неизменность JSON.
Ошибки покрывают пути, типы узлов, UTF-8, опции и аргументы каждой команды.
REPL демонстрирует продолжение после ошибки и обновление приглашения.

## Проверка пятого этапа и флагов ls

```bash
./run.sh --vfs vfs/stage5.json
./run.sh --vfs vfs/stage5.json --script scripts/stage5_success.txt
bash scripts/stage5_all.sh
```

Первый вызов запускает REPL для ручной проверки. Успешный сценарий проверяет
все сочетания `ls -l/-h/-a`, отдельные флаги, файлы и пустые каталоги,
`rm` с обычным и рекурсивным удалением, `-f`, `rmdir`, абсолютные
и относительные пути, кавычки и `--`. Скрипт реальной ОС запускает успешный
сценарий, все 23 ошибочных `stage5_*.txt` и REPL с продолжением после ошибки.
Каждый вызов загружает свежую VFS. Ошибочные сценарии отдельно проверяют
пути, типы узлов, непустые каталоги, защиту корня и текущего каталога,
аргументы и флаги. Скрипт проверяет код `1`; автотесты также проверяют
остановку до `must_not_execute`, неизменность всех JSON и независимость сеансов.

## Тесты

Linux:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Windows:

```bat
set PYTHONPATH=src
py -m unittest discover -s tests -v
```

Проверяются парсер, команды, REPL, стартовые скрипты, загрузка JSON,
base64, глубокие пути, ошибки формата, независимость сеансов, неизменность
источника и работа после его удаления. Тесты этапа 4 проверяют режимы `ls`
и `uniq`, навигацию `cd`, имя пользователя, ошибочные команды и сценарии CLI.
Тесты этапа 5 проверяют удаление, режимы `ls -l/-h/-a`,
границы размеров, UTF-8-байты, частичное выполнение и защиту каталогов.
Для полного набора тестов нужен Bash, в том числе при запуске в Windows.
Сборка не требуется: используется стандартная библиотека Python.

## Пример

```text
igor@modern:/$ ls
data.bin
empty.txt
folder
lines.txt
igor@modern:/$ cd folder
igor@modern:/folder$ uniq "two words.txt"
x
y
igor@modern:/folder$ whoami
igor
igor@modern:/folder$ cd /missing
error: no such file or directory: /missing
igor@modern:/folder$ exit
Execution finished with errors.
```

Пример использует `vfs/stage4.json`. Имя пользователя и компьютера
зависят от реальной ОС. Все файловые команды работают только с VFS в памяти.
